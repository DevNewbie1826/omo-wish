# 계층적 DAG 설계 및 단계적 수렴을 위한 최상위 규칙

## 0. 최상위 설계 원칙

모든 작업 계획과 DAG(Directed Acyclic Graph)는 **재귀적 계층 분해(Recursive Hierarchical Decomposition)**, **원자 작업 실행(Atomic Task Execution)**, **계층적 단계 수렴(Hierarchical Progressive Convergence)** 원칙에 따라 설계한다.

모든 복합 작업은 최상위 목표에서 시작하여 더 이상 실질적으로 분해할 수 없는 최소 실행 작업까지 재귀적으로 분해해야 한다.

실행은 최소 실행 작업을 기반으로 수행하며, 실행 결과는 반드시 자신이 속한 직접적인 상위 계층에서 검증 및 통합한 후 다음 상위 계층으로 전달한다.

**최상위 목표에서 최하위 작업까지는 Top-Down으로 분해하고, 실행 결과는 최하위 작업에서 최상위 목표까지 Bottom-Up으로 단계적으로 수렴시킨다.**

이 원칙은 모든 DAG 생성, 수정, 최적화 및 재구성 과정에서 반드시 유지해야 하는 최상위 불변 조건이다.

---

## 1. 재귀적 계층 분해 원칙

### 1.1 완전 분해

모든 작업은 다음과 같은 계층 구조를 기반으로 분해한다.

**최상위 목표 → 대분류 → 중분류 → 소분류 → 세부 작업 → 최소 실행 작업**

위 계층 명칭은 개념적인 예시이며, 실제 계층의 수와 깊이는 작업의 복잡도에 따라 동적으로 결정한다.

규칙:

1. 모든 최상위 목표를 의미적으로 구분되는 하위 작업으로 분해한다.
2. 각 하위 작업을 독립적으로 분석하여 추가 분해 가능성을 평가한다.
3. 추가 분해가 실질적인 실행·검증·관리상의 이점을 제공한다면 반드시 재귀적으로 분해한다.
4. 더 이상 의미 있는 분해가 불가능할 때까지 이 과정을 반복한다.
5. 모든 최하위 작업은 최소 실행 작업(Atomic Task)의 정의를 만족해야 한다.
6. 분해 깊이나 하위 작업의 개수를 임의로 고정하지 않는다.
7. 서로 다른 작업 분기는 서로 다른 계층 깊이를 가질 수 있다.
8. 계층의 균형을 맞추기 위한 불필요한 작업이나 형식적인 중간 노드는 생성하지 않는다.

### 1.2 분해의 완전성

각 복합 작업의 하위 작업 집합은 해당 상위 작업의 목표와 책임 범위를 완전히 충족해야 한다.

- 상위 작업의 필수 책임이 누락되어서는 안 된다.
- 동일한 책임이 불필요하게 여러 하위 작업에 중복되어서는 안 된다.
- 각 하위 작업은 명확한 결과물을 가져야 한다.
- 하위 작업의 결과들을 통합하면 상위 작업의 완료 조건을 충족할 수 있어야 한다.
- 결과 통합만으로 상위 작업을 완료할 수 없다면 필요한 실행 작업을 추가하거나 분해 구조를 수정한다.

## 2. 최소 실행 작업(Atomic Task) 정의

최소 실행 작업은 더 이상 실질적으로 분해할 필요가 없는, 실제 실행 가능한 가장 작은 작업 단위이다.

모든 최소 실행 작업은 다음 조건을 충족해야 한다.

1. **단일 책임:** 하나의 명확한 실행 목적을 가진다.
2. **명확한 입력:** 실행에 필요한 입력 데이터와 선행 조건이 정의되어 있다.
3. **명확한 출력:** 실행 완료 후 생성되는 결과물이 정의되어 있다.
4. **실행 가능성:** 지정된 실행 주체가 해당 작업을 실제로 수행할 수 있다.
5. **검증 가능성:** 성공·실패 및 완료 여부를 객관적으로 검증할 수 있다.
6. **분해 종료 조건:** 추가 분해가 독립 실행, 병렬화, 검증, 오류 격리 또는 관리 측면에서 실질적인 이점을 제공하지 않는다.
7. **의존성 명확성:** 실행에 필요한 선행 작업과 외부 의존성이 명확하다.

위 조건을 만족하지 않는 작업은 최소 실행 작업으로 인정하지 않고 추가 분해하거나 재정의한다.

단순히 작업의 설명이 짧다는 이유로 최소 실행 작업으로 판단해서는 안 된다.

반대로 기술적으로 더 작은 행동으로 나눌 수 있다는 이유만으로 의미 없는 분해를 반복해서도 안 된다.

**원자성의 기준은 물리적으로 더 이상 나눌 수 없다는 뜻이 아니라, 실행·검증·관리 관점에서 추가 분해의 실질적인 가치가 없다는 뜻이다.**

## 3. 세 가지 관계의 엄격한 분리

DAG를 구성할 때 다음 세 가지 관계를 반드시 구분한다.

### 3.1 작업 분류 관계 (Decomposition Hierarchy)

작업 분류 관계는 특정 작업이 어떤 상위 작업에 소속되는지를 정의한다.

- 모든 작업은 하나의 명확한 분류 위치를 갖는다.
- 최상위 목표를 제외한 모든 작업은 직접적인 상위 작업을 갖는다.
- 상위 작업은 하나 이상의 하위 작업을 포함할 수 있다.
- 분류 관계 자체가 실행 순서를 의미하지는 않는다.
- 분류 계층에는 순환 참조가 존재해서는 안 된다.

### 3.2 실행 의존성 관계 (Execution Dependency)

실행 의존성 관계는 특정 작업의 실행 또는 완료가 다른 작업의 실행에 필요한지를 정의한다.

- 실제 데이터·자원·상태·논리적 선행 조건이 존재하는 경우에만 실행 의존성을 생성한다.
- 서로 독립적인 작업에는 불필요한 실행 의존성을 생성하지 않는다.
- 서로 다른 분류 계층에 속하는 작업 간에도 실제 의존성이 있다면 이를 명시할 수 있다.
- 모든 실행 의존성은 방향성을 가져야 한다.
- 실행 의존성 그래프에는 순환 참조가 존재해서는 안 된다.
- 단순히 같은 상위 작업에 속한다는 이유로 작업 간 순차 실행을 강제하지 않는다.

### 3.3 결과 수렴 관계 (Result Convergence)

결과 수렴 관계는 실행 결과가 어느 상위 작업으로 전달되고 검증·통합되는지를 정의한다.

- 모든 최소 실행 작업의 결과는 자신의 직접적인 상위 작업으로 전달한다.
- 각 상위 작업은 직접적인 하위 작업의 결과만을 수렴 대상으로 삼는다.
- 상위 작업은 필요한 모든 하위 결과가 준비되면 이를 검증·통합한다.
- 검증과 통합이 완료된 결과만 다음 상위 계층으로 전달한다.
- 직접적인 상위 계층을 건너뛰는 결과 수렴 관계는 생성하지 않는다.
- 최상위 결과는 모든 필수 하위 계층의 단계적 수렴을 거쳐 생성되어야 한다.

**분류 관계, 실행 의존성 관계, 결과 수렴 관계는 서로 다른 의미를 갖는다. 하나의 관계를 다른 관계로 암묵적으로 대체해서는 안 된다.**

## 4. 계층적 단계 수렴 원칙

### 4.1 Bottom-Up 수렴

모든 실행 결과는 최소 실행 작업에서 시작하여 최상위 목표까지 단계적으로 수렴한다.

기본 흐름:

**최소 실행 작업 → 직접 상위 작업의 검증·통합 → 다음 상위 작업의 검증·통합 → … → 최상위 목표**

규칙:

1. 각 최소 실행 작업은 자신의 실행 결과와 완료 상태를 생성한다.
2. 직접적인 상위 작업은 해당 결과를 수집하고 검증한다.
3. 상위 작업의 필수 하위 결과가 준비되면 통합을 수행한다.
4. 상위 작업의 완료 조건을 검증한다.
5. 검증을 통과한 상위 작업의 결과를 다음 상위 계층으로 전달한다.
6. 최상위 목표에 도달할 때까지 이를 재귀적으로 반복한다.

### 4.2 중간 계층 생략 금지

다음 구조를 절대 허용하지 않는다.

- 최소 실행 작업이 중간 계층을 생략하고 최상위 결과 노드에 직접 연결되는 구조
- 여러 계층의 작업 결과를 하나의 최종 노드에서 한 번에 통합하는 구조
- 하위 계층의 검증 없이 최상위 계층에서 직접 검증하는 구조
- 이미 존재하는 중간 통합 계층을 우회하는 수렴 경로
- 전체 작업을 최소 작업으로만 분해한 뒤 단일 최종 통합 노드에 직접 연결하는 평면적 수렴 구조

모든 결과 수렴 경로는 실제 분류 계층에 존재하는 직접적인 상위 작업을 차례로 거쳐야 한다.

단, 원래 분류 구조에 존재하지 않는 계층을 형식적으로 추가할 필요는 없다.

### 4.3 통합 노드의 책임

각 상위 작업은 자신의 하위 결과에 대해 다음 책임을 수행한다.

- 결과 수집
- 입력 및 출력 계약 검증
- 누락 및 실패 여부 확인
- 결과 간 정합성 검증
- 필요한 결과 통합
- 상위 작업의 완료 조건 검증
- 다음 상위 계층에 전달할 결과 생성

통합 과정에 별도의 실행이나 계산이 필요하면 이를 실행 작업으로 명시한다.

단순한 결과 전달이나 상태 집계만 필요한 경우에는 독립적인 실행 작업을 추가하지 않고 상위 작업의 완료 및 검증 책임으로 처리할 수 있다.

**모든 중간 계층은 수렴 과정에 참여해야 하지만, 모든 중간 계층이 별도의 실행 작업을 필요로 하는 것은 아니다.**

## 5. 불필요한 계층 및 노드 생성 금지

작업을 충분히 분해하는 것과 불필요하게 복잡하게 만드는 것은 구분해야 한다.

다음 사항을 금지한다.

1. 정해진 계층 수를 맞추기 위해 의미 없는 중간 작업 생성
2. 동일한 책임을 이름만 바꾸어 여러 계층에 중복 배치
3. 실질적인 검증·통합·관리 책임이 없는 형식적인 통합 작업 생성
4. 단일 작업을 불필요한 전달 노드의 연속으로 연결
5. 실제 실행 의존성이 없는 작업 사이에 순차 실행 관계 생성
6. 지나치게 작은 작업으로 분해하여 실행 비용과 관리 비용만 증가시키는 구조

각 중간 계층은 최소한 다음 중 하나 이상의 명확한 목적을 가져야 한다.

- 의미적으로 독립된 책임 범위
- 관련 하위 작업의 논리적 그룹화
- 결과의 통합 및 검증 경계
- 오류 격리 및 복구 경계
- 독립적인 관리 또는 실행 책임
- 상위 목표에 필요한 명확한 중간 결과물

이러한 목적이 전혀 없다면 해당 계층을 제거하거나 인접 계층에 병합한다.

단, 계층을 제거하거나 병합한 후에도 남아 있는 모든 수렴 경로는 반드시 직접적인 상위 계층을 따라야 한다.

## 6. 병렬 실행과 의존성 최적화

DAG는 계층적 구조를 유지하면서 가능한 실행 병렬성을 보장해야 한다.

1. 선행 의존성이 충족된 최소 실행 작업은 즉시 실행 가능한 상태가 된다.
2. 서로 독립적인 작업들은 병렬 실행할 수 있도록 구성한다.
3. 분류 계층상의 위치만으로 실행 순서를 제한하지 않는다.
4. 실제 데이터 또는 자원 의존성이 존재할 경우에만 실행 순서를 강제한다.
5. 동일 계층 또는 서로 다른 계층에 속한 작업이라도 독립적이면 병렬로 실행할 수 있다.
6. 상위 계층의 결과 수렴은 해당 상위 작업에 필요한 하위 결과와 검증 조건이 충족된 후 수행한다.
7. 불필요한 대기와 직렬화를 방지한다.

**분류 구조는 책임을 정의하고, 실행 DAG는 실행 순서를 정의하며, 수렴 구조는 결과의 통합 경로를 정의한다.**

이 세 구조를 혼동하여 병렬성을 손상해서는 안 된다.

---

## 7. 실패 처리 및 검증 전파

모든 계층은 자신이 책임지는 작업 결과의 성공·실패를 명확히 관리해야 한다.

1. 최소 실행 작업이 실패하면 해당 실패를 직접적인 상위 작업에 보고한다.
2. 상위 작업은 실패 유형에 따라 재시도, 재실행, 복구 또는 실패 전파를 결정한다.
3. 실패가 복구되지 않았고 상위 작업의 완료 조건을 충족할 수 없다면 해당 상위 작업을 성공으로 처리하지 않는다.
4. 상위 작업의 검증에 실패한 결과는 검증된 최종 결과로 상위 계층에 전달하지 않는다.
5. 실패 및 복구 상태 역시 직접적인 상위 계층을 통해 단계적으로 전달한다.
6. 특정 하위 작업의 실패가 다른 독립 작업의 실행을 불필요하게 중단시키지 않도록 한다.
7. 최상위 목표는 사전에 정의된 성공 조건을 만족한 경우에만 완료 처리한다.

실패 처리 역시 작업 분류 및 수렴 계층을 존중해야 한다.

## 8. DAG 생성 절차

모든 DAG는 다음 절차에 따라 구성한다.

### 단계 1. 최상위 목표 정의

최종 목표, 입력, 출력, 제약 조건 및 완료 조건을 명확히 정의한다.

### 단계 2. 계층적 작업 분해

최상위 목표를 의미적으로 독립된 하위 작업으로 분해한다.

각 하위 작업에 대해 동일한 분해 과정을 재귀적으로 수행한다.

### 단계 3. 최소 실행 작업 확정

최하위 작업이 원자성 조건을 만족하는지 검증한다.

조건을 만족하지 않는 작업은 재분해한다.

### 단계 4. 분류 계층 검증

각 작업의 상위·하위 관계, 책임 범위, 중복 여부 및 누락 여부를 검증한다.

불필요한 계층은 제거한다.

### 단계 5. 실행 의존성 구성

실제 선행 조건을 분석하여 최소 실행 작업과 필요한 실행·검증 작업 사이의 의존성을 정의한다.

불필요한 순차 실행 관계는 제거한다.

### 단계 6. 결과 수렴 구조 구성

각 작업의 결과가 직접적인 상위 계층으로 전달되도록 수렴 구조를 정의한다.

각 중간 계층의 검증 및 통합 책임을 명시한다.

### 단계 7. 병렬성 최적화

실행 의존성을 위반하지 않는 범위에서 독립 작업의 병렬 실행 가능성을 최대화한다.

### 단계 8. 전체 구조 검증

모든 불변 조건과 검증 항목을 검사한다.

### 단계 9. 위반 사항 재구성

검증에 실패한 부분을 수정하고 전체 검증을 반복한다.

모든 필수 조건을 만족할 때만 DAG 구성을 완료한다.

## 9. 필수 검증 항목

DAG 생성 후 다음 항목을 모두 확인한다.

### 분해 검증

- [ ] 모든 복합 작업이 충분히 재귀적으로 분해되었는가?
- [ ] 모든 최하위 작업이 원자성 조건을 만족하는가?
- [ ] 상위 작업의 필수 책임이 하위 작업에 빠짐없이 반영되었는가?
- [ ] 중복되거나 의미 없는 작업이 존재하지 않는가?
- [ ] 불필요한 계층이 생성되지 않았는가?

### 관계 검증

- [ ] 작업 분류 관계와 실행 의존성이 명확하게 구분되어 있는가?
- [ ] 실행 의존성과 결과 수렴 관계가 구분되어 있는가?
- [ ] 모든 비최상위 작업이 직접적인 상위 작업을 가지는가?
- [ ] 실행 의존성이 실제 선행 조건에 근거하는가?
- [ ] 분류 계층과 실행 의존성 그래프에 순환 참조가 없는가?

### 수렴 검증

- [ ] 모든 최소 실행 작업의 결과가 직접적인 상위 작업으로 전달되는가?
- [ ] 중간 계층을 건너뛰는 수렴 경로가 존재하지 않는가?
- [ ] 각 상위 작업이 자신의 하위 결과를 검증하고 통합하는가?
- [ ] 모든 필수 중간 결과가 검증된 후 상위 계층으로 전달되는가?
- [ ] 여러 계층의 결과를 최상위 노드에서 한 번에 통합하는 구조가 없는가?
- [ ] 최종 결과가 실제로 존재하는 모든 중간 계층을 거쳐 생성되는가?

### 실행 검증

- [ ] 독립 실행 가능한 작업들이 불필요하게 직렬화되지 않았는가?
- [ ] 모든 실행 작업이 필요한 입력과 선행 조건을 보장받는가?
- [ ] 모든 작업의 완료 조건이 정의되어 있는가?
- [ ] 실패 처리와 복구 경로가 명확한가?
- [ ] 작업 결과가 중복 실행이나 잘못된 수렴으로 인해 오염될 가능성이 없는가?

위 검증 항목 중 하나라도 실패하면 해당 DAG는 유효하지 않은 것으로 판단하고 수정한다.

## 10. 절대 불변 조건 (Non-Negotiable Invariants)

다음 조건은 어떤 상황에서도 위반해서는 안 된다.

**Invariant 1 — Recursive Decomposition**

모든 복합 작업은 추가 분해의 실질적 이점이 없어질 때까지 재귀적으로 분해한다.

**Invariant 2 — Atomic Leaf Tasks**

모든 최하위 실행 작업은 명확한 입력, 출력, 책임, 실행 조건 및 완료 기준을 갖춘 최소 실행 단위여야 한다.

**Invariant 3 — Explicit Hierarchy**

모든 비최상위 작업은 하나의 직접적인 상위 분류 작업을 가진다.

**Invariant 4 — Strict Parent-Level Convergence**

모든 결과 수렴은 반드시 직접적인 상위 계층을 거쳐야 하며, 실제로 존재하는 중간 계층을 건너뛸 수 없다.

**Invariant 5 — No Flat Convergence**

복합 작업에 여러 중간 계층이 존재함에도 불구하고 모든 최소 작업의 결과를 단일 최종 노드에 직접 연결하는 평면적 수렴 구조를 금지한다.

**Invariant 6 — Meaningful Hierarchy**

모든 계층은 명확한 책임이나 구조적 목적을 가져야 한다. 계층의 깊이를 늘리기 위한 형식적인 노드는 금지한다.

**Invariant 7 — Separation of Concerns**

작업 분류, 실행 의존성, 결과 수렴을 서로 독립적인 관계로 정의하고 관리한다.

**Invariant 8 — Dependency-Driven Execution**

실행 순서는 실제 의존성에 의해서만 결정한다. 분류 관계나 수렴 계층만을 이유로 불필요한 실행 순서를 강제하지 않는다.

**Invariant 9 — Acyclic Execution**

모든 실행 의존성 그래프는 순환하지 않아야 하며 유효한 위상 정렬이 가능해야 한다.

**Invariant 10 — Validated Progressive Completion**

각 계층의 완료 상태는 해당 계층의 필수 하위 결과와 검증 조건을 충족한 후에만 상위 계층으로 전달한다.

## 11. 최종 실행 명령

DAG를 생성할 때 단순히 작업 목록을 나열하지 마라.

반드시 다음을 만족하는 실행 가능한 계층적 DAG를 설계하라.

1. 최상위 목표에서 시작하여 최소 실행 작업까지 완전히 분해한다.
2. 각 작업의 분류 위치, 실행 조건, 입력, 출력 및 완료 기준을 정의한다.
3. 실행 의존성을 실제 선행 조건에 따라 구성한다.
4. 최소 실행 작업부터 직접적인 상위 계층으로 결과를 단계적으로 수렴시킨다.
5. 모든 중간 계층에서 필요한 검증 및 통합을 수행한다.
6. 존재하는 중간 계층을 절대로 건너뛰지 않는다.
7. 불필요한 계층, 형식적인 통합 작업, 가짜 의존성을 생성하지 않는다.
8. 가능한 병렬성을 최대한 보존한다.
9. 모든 불변 조건을 자동 검증하고 위반하면 재구성한다.
10. 모든 검증을 통과한 구조만 최종 DAG로 확정한다.

### 최종 핵심 명령

**Top-Down으로 의미 있는 최소 실행 단위까지 완전히 분해하라.**

**Bottom-Up으로 실제 계층의 직접적인 부모 노드를 통해 한 단계씩 검증·통합하며 수렴하라.**

**중간 수렴 단계를 건너뛰지 마라.**

**불필요한 중간 계층을 만들지 마라.**

**실행 의존성과 결과 수렴을 혼동하지 마라.**

**구조적 정확성, 원자성, 검증 가능성 및 병렬 실행 가능성을 동시에 보장하라.**
