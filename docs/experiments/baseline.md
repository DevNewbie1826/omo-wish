# 기준선 계산 (2026-10-27)

이 파일은 `docs/experiments/ledger.md`의 기준선을 임시 경로에 의존하지 않고 재현할 수 있게 고정한 기록입니다.

- 파일: `wish-metrics.csv` (41컬럼, 115 PR 행 + 헤더 1행)
- sha256: `925ca476c03fcf6d360e1f7f4538a39b29357f53c5f2f9842a028b7eb358d565`
- 행 수: 116줄 (헤더 포함)
- 스냅샷 시각: 2026-10-27
- 원본 위치는 실행 세션의 임시 경로였습니다. 이 파일의 수치와 계산식이 판정 기준입니다.
- 저장소 안 재계산용 추출본: `docs/experiments/baseline-data.csv` (병합 104행, 사용한 9개 컬럼만).

## 계산식

CSV를 RFC4180 방식(따옴표 인식)으로 파싱하고 `state == MERGED` 행만 사용했습니다.

- 최종 리뷰 REVISE ≥1: `final_review_revise_rounds > 0`
- 최종 리뷰 REVISE ≥2: `final_review_revise_rounds >= 2`
- 열림→병합: `open_to_merge_minutes`의 중앙값(짝수면 두 가운데 값의 평균)
- delta 회차 있음: `delta_revise_rounds > 0`
- 열린 뒤 커밋 구간: `commits_after_open` ≥3 / <3, REVISE율은 `all_revise_rounds > 0`
- 꼬리: `all_revise_rounds >= 4`

## 읽는 법

- 회차의 76%(70/92)가 최종 리뷰에서 발생하므로, 실험은 step 9를 겨냥합니다.
- 최종 리뷰 REVISE가 0회인 PR(n=62)과 1회 이상인 PR(n=42)의 중앙값이 51.3 → 171.8분으로 약 3.3배입니다. "회차가 늘 때마다 비례한다"는 뜻이 아니라 두 그룹의 비교입니다.
- 열린 뒤 커밋이 3건 이상인 PR은 75.7%가 REVISE를 겪습니다(3건 미만 25.4%). 원인인지 결과인지는 이 데이터로 가를 수 없으므로, 헤드 동결(E6)은 원인 쪽 가설로 따로 검증합니다.
