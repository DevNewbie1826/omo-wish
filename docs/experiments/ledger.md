# 리뷰 개선 실험 장부

wish 스킬의 최종 리뷰(step 9, `category: ultrabrain`) 단계를 겨냥한 실험 시리즈의 장부입니다. 소유자 규칙: **한 실험에 한 변수**, 시작 전에 **취소 기준(지표·임계값·판정 PR 수)** 을 이 파일에 등록, 결과가 개선이 아니면 **되돌리고 수치와 이유를 기록한 뒤 다음 실험으로 계속**.

## 기준선 (2026-10-27 측정)

출처: 2026-10-27 시점 `wish-metrics.csv`(115행, 병합 104건)를 이 저장소의 실행 세션이 다시 계산한 값. 계산 요약과 사용한 104행 추출본(`baseline-data.csv`)을 함께 커밋해 두어 판정이 임시 경로에 의존하지 않고 저장소 안에서 재계산됩니다.

| 지표 | 값 |
| --- | --- |
| 최종 리뷰 REVISE ≥1 | 42/104 (40.4%) |
| 최종 리뷰 REVISE ≥2 | 17/104 (16.3%) |
| 열림→병합 중앙 | 92.8분 (REVISE 0: 51.3분 n=62 / ≥1: 171.8분 n=42) |
| delta 회차가 있는 PR | 8/104, 중앙 341.7분 (없는 PR 86.0분) |
| 열린 뒤 커밋 ≥3 | 37건, REVISE율 75.7%, 중앙 252.0분 (＜3: 67건, 25.4%, 56.1분) |
| 꼬리(REVISE ≥4) | 8/104 |

참고: 독립 분석 문서는 ≥2를 15건, 열린 뒤 커밋 ≥3의 REVISE율을 70%로 적었지만, 같은 CSV를 다른 컬럼으로 계산한 값입니다. 이 장부는 위 표를 기준선으로 씁니다.

## 세는 방법 (판정 전에 고정)

- **회차 수** = ultrabrain REVISE 판정 수 + `not fixed` 게이트 루프 수. 게이트가 호출을 막은 회차도 회차로 셉니다(호출 수만 세면 처치가 과소 계상됨).
- **게이트가 막은 회차의 기록**: dispatch 시각 칸은 `not dispatched`, 판정 시각 칸은 `gate-blocked`로 적습니다. 소요 시간은 그 회차의 수정 시작~재게이트 시간이며, dispatch→verdict 대기 시간과 섞지 않습니다. 호출 수는 늘지 않습니다.
- **열림→병합** = `gh pr view --json createdAt,mergedAt` 차이(분).
- **회차 분** = dispatch 시각과 verdict 수신 시각의 차이(초 단위 기록, 분으로 표시).
- **게이트 행** = fixed / not fixed / no command 수.

## 공유 장부 (5팔 공통)

이 디렉터리가 다섯 팔(C2 #41, E2+C3 #42, C1 #43, E6+E9 #44, C6 #45)의 **단일 기록 장소**입니다. 세 파일이 역할을 나누고, 다른 경로에 사본을 두지 않습니다.

| 파일 | 내용 |
| --- | --- |
| `ledger.md` | 실험 등록·취소 기준·판정 기록(권위) |
| `measurements.csv` | PR 단위 한 행 (아래 열 순서 고정) |
| `rounds.csv` | 리뷰 회차 단위 한 행 (아래 열 순서 고정) |

`measurements.csv` 열: `pr, repo, arm, common_arms, route_class, size_bucket, stacked_on, opened_at, merged_at, open_to_merge_min, rounds_total, ultrabrain_calls, code_reviewer_calls, architect_calls, content_commits_after_approval, step12_result, post_merge_refix, blind_rereview, invalid_flag, notes`

`rounds.csv` 열: `pr, round_index, round_kind, verdict_head, dispatch_at, verdict_at, minutes, reviewer, reviewer_family, defect_count, defect_axes, counterexample_present, gate_rows_fixed, gate_rows_not_fixed, gate_rows_no_command, c2_split, axis_lines_present, verdict_line_present, verdict_head_match`

- `round_kind`은 `first`, `revise`, `delta`, `gate-blocked` 중 하나입니다. 게이트가 막은 회차는 `dispatch_at`에 `not dispatched`를 적습니다.
- `common_arms`에는 그 PR에 같이 적용된 공통 기반(예: `E6+E9`)을 적습니다. 리뷰어·게이트 팔은 PR당 하나만 적습니다.
- `invalid_flag`는 공급자 524, 세션 정지, 리베이스·충돌 해소가 시간 지표를 오염시킨 경우 채우고, 해당 PR은 중앙값에서 제외합니다.
- `gate_rows_*`는 C1의 표를, `c2_split`은 C2의 합집합 분해(A만/B만/둘 다+계열명)를, `axis_lines_present`·`counterexample_present`는 E2+C3의 준수 필드를, `verdict_line_present`·`verdict_head_match`는 E9를 기록합니다.
- 측정은 소유자의 배정 승인 뒤에 시작합니다. 그 전까지 두 CSV는 헤더만 둡니다.

## 공통 측정 (모든 실험)

PR마다: 열림→병합 분, 헤드 최종 push 시각, 최종 리뷰 호출 수, 회차별 dispatch→verdict 분, 회차별 결함 수, 게이트 행(fixed/not fixed/no command), 병합 후 step 12 결과, 병합 뒤 재수정 여부.
블록마다: 무작위 5건 blind 재리뷰(새 눈으로 계약 내 코드 결함 확인).

## 공통 품질 가드 (하나라도 걸리면 그 실험 즉시 취소)

1. 병합 후 step 12 실패.
2. 병합 뒤 그 PR을 다시 고치는 커밋/PR.
3. blind 재리뷰에서 계약 내 코드 결함 발견(그 실험이 줄인 검사가 놓친 것).
4. 꼬리(≥4회) 비율 악화.

## 실행 순서

C1과 C1b는 같은 PR에서 함께 배포됩니다. 그래서 시간 지표만으로 실패하면 어느 쪽 때문인지 가를 수 없으므로, **C1b는 시간 지표가 나빠져도 C1을 취소하지 않고, 시간만 실패한 경우에는 게이트 단독 재판정(다음 12 PR)을 한 번** 합니다. 이 혼입 사실을 취소 사유 기록에 함께 적습니다.

1. **C1** (진행 중, 소유자 지시로 유지)
2. **E6 + E9** — 한 문장 + 계측. 품질 위험이 0에 가깝고, C1이 남기는 "판정 뒤 커밋" 교란을 없애 이후 측정을 깨끗하게 만듭니다.
3. **E2** — 회차 자체를 줄이는 다음 큰 레버.
4. **E7** — 꼬리 절단.
5. **C4** — 회차당 시간.
6. **C2** — 1회차 폭 확대.
7. **E8** — S부류 예방(step 6 쪽).
8. **E10** — 소유자 승인 뒤.

## 기록 형식

실행(run)은 최종 보고에 **회차별 상세**를 남깁니다: 회차, 판정 헤드, dispatch 시각, verdict 시각, 분, 결함 수, 게이트 행, PR 단위 호출 수, step 12 결과.

시리즈 실행자는 이 장부에 **PR 단위 요약**을 남깁니다:

```
| PR | 실험 | 열림→병합(분) | 회차 수(REVISE+not fixed) | 회차별 분 | 게이트 행 fixed/not fixed/no command | 결함 수 | step12 | 재수정 | 비고 |
```

블록 단위 표(품질 확인):

```
| 블록 | 실험 | 표본 5 PR | blind 재리뷰 결과 | 재수정 여부 | 판정 |
```
