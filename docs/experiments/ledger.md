# 리뷰 개선 실험 장부

wish 스킬의 최종 리뷰(step 9, `category: ultrabrain`) 단계를 겨냥한 실험 시리즈의 장부입니다. 소유자 규칙: **한 실험에 한 변수**, 시작 전에 **취소 기준(지표·임계값·판정 PR 수)** 을 이 파일에 등록, 결과가 개선이 아니면 **되돌리고 수치와 이유를 기록한 뒤 다음 실험으로 계속**.

## 기준선 (2026-10-27 측정)

| 최종 리뷰 REVISE ≥2 | 17/104 (16.3%) |
| 열림→병합 중앙 | 92.8분 (REVISE 0: 51.3분 n=62 / ≥1: 171.8분 n=42) |

## 세는 방법 (판정 전에 고정)

- **회차 수** = ultrabrain REVISE 판정 수 + `not fixed` 게이트 루프 수. 게이트가 호출을 막은 회차도 회차로 셉니다(호출 수만 세면 처치가 과소 계상됨).
- **열림→병합** = `gh pr view --json createdAt,mergedAt` 차이(분).
- **회차 분** = dispatch 시각과 verdict 수신 시각의 차이(초 단위 기록, 분으로 표시).
- **게이트 행** = fixed / not fixed / no command 수.

## 공통 측정 (모든 실험)

PR마다: 열림→병합 분, 최종 리뷰 호출 수, 회차별 dispatch→verdict 분, 회차별 결함 수, 게이트 행(fixed/not fixed/no command), 병합 후 step 12 결과, 병합 뒤 재수정 여부.
블록마다: 무작위 5건 blind 재리뷰(새 눈으로 계약 내 코드 결함 확인).

## 공통 품질 가드 (하나라도 걸리면 그 실험 즉시 취소)

1. 병합 후 step 12 실패.
2. 병합 뒤 그 PR을 다시 고치는 커밋/PR.
3. blind 재리뷰에서 계약 내 코드 결함 발견(그 실험이 줄인 검사가 놓친 것).
4. 꼬리(≥4회) 비율 악화.

## 실행 순서

1. **C1** (진행 중, 소유자 지시로 유지)
2. **E6 + E9** — 한 문장 + 계측. 품질 위험이 0에 가깝고, C1이 남기는 "판정 뒤 커밋" 교란을 없애 이후 측정을 깨끗하게 만듭니다.
3. **E2** — 회차 자체를 줄이는 다음 큰 레버.
4. **E7** — 꼬리 절단.
5. **C4** — 회차당 시간.
6. **C2** — 1회차 폭 확대.
7. **E8** — S부류 예방(step 6 쪽).
8. **E10** — 소유자 승인 뒤.

## 기록 형식

실행(run)은 최종 보고에 **회차별 상세**를 남깁니다: 회차, 판정 헤드, dispatch 시각, verdict 시각, 분, 결함 수, 게이트 행, PR 단위 호출 수, step 12 결과.

시리즈 실행자는 이 장부에 **PR 단위 요약**을 남깁니다:

```
| PR | 실험 | 열림→병합(분) | 회차 수(REVISE+not fixed) | 회차별 분 | 게이트 행 fixed/not fixed/no command | 결함 수 | step12 | 재수정 | 비고 |
```

블록 단위 표(품질 확인):

```
| 블록 | 실험 | 표본 5 PR | blind 재리뷰 결과 | 재수정 여부 | 판정 |
```
