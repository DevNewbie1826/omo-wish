# 리뷰 개선 실험 장부

wish 스킬의 최종 리뷰(step 9, `category: ultrabrain`) 단계를 겨냥한 실험 시리즈의 장부입니다. 소유자 규칙: **한 실험에 한 변수**, 시작 전에 **취소 기준(지표·임계값·판정 PR 수)** 을 이 파일에 등록, 결과가 개선이 아니면 **되돌리고 수치와 이유를 기록한 뒤 다음 실험으로 계속**.

## 세는 방법 (판정 전에 고정)

- **회차 수** = ultrabrain REVISE 판정 수 + `not fixed` 게이트 루프 수. 게이트가 호출을 막은 회차도 회차로 셉니다(호출 수만 세면 처치가 과소 계상됨).
- **게이트가 막은 회차의 기록**: dispatch 시각 칸은 `not dispatched`, 판정 시각 칸은 `gate-blocked`로 적습니다. 소요 시간은 그 회차의 수정 시작~재게이트 시간이며, dispatch→verdict 대기 시간과 섞지 않습니다. 호출 수는 늘지 않습니다.
- **열림→병합** = `gh pr view --json createdAt,mergedAt` 차이(분).
- **회차 분** = dispatch 시각과 verdict 수신 시각의 차이(초 단위 기록, 분으로 표시).
- **게이트 행** = fixed / not fixed / no command 수.

### 판정 순서 (모든 행 공통)

모든 행은 같은 순서로 판정한다: (0) 공통 품질 가드 위반이면 취소 (1) 그 행의 취소 조건이면 취소 (2) 그 행의 계속 조건이면 계속 (3) 둘 다 아니면 취소. 행이 연장을 명시한 경우에만 첫 판정 시점의 (3)을 한 번의 연장으로 대신하고, 연장 뒤에는 (0)~(2) 다음이 바로 취소다. 취소 조건과 계속 조건이 동시에 참이면 취소가 이긴다. 이 기본값은 "개선이 아니면 취소" 규칙과 같다.

`invalid_flag`가 붙은 PR은 시간 지표의 중앙값에서만 빼고, 비율(k/N)의 분모에서는 빼지 않는다(분모가 바뀌면 25%/40% 경계가 흔들린다) — 단 세션 정지로 지표 자체가 없는 PR은 분모에서도 빼고 그 사실을 기록한다.

### 테스트 코드 전용 라운드 (별도 집계)

REVISE 라운드 중 블로킹 파인딩이 전부 테스트 산출물에 떨어지는 라운드는 따로 센다. 규칙(측정 보고서와 동일): 파인딩이 요구하는 수정이 `test/`, `*.test.ts`, `*_test.go`, `test/qa/`, 변이·가드·QA 픽스처에 떨어지거나, 가드가 절대 실패하지 않는(vacuous) 결함·커버리지 누락·“cannot fail” 테스트를 고치라고 요구하면 **TEST**; 시험이 생산 코드 결함을 관찰만 하면 TEST가 아니고 **PROD**; 계획·계약·문서·증거 문제는 **PLAN**; 섞이면 **MIXED**. 비차단 LOW/메모는 라운드를 REVISE로 만든 항목이 아니므로 세지 않는다.

기준선(측정 보고서, 2026-10-27): genie 병합 104 PR  74라운드 중 TEST 10 (13.5%), 파인딩 13/68 (19.1%); genie 열린 9 PR은 16/43 (37.2%, 그 중 #63 한 건이 15연속 TEST 라운드·20시간); agent-sense 22라운드 중 7 (31.8%). #63 제외 시 열린 PR은 1/13 (7.7%).

규칙: 각 팔의 결과 보고에는 (a) TEST 전용 라운드 수/전체 라운드와 시간 축 위치, (b) 그 팔이 TEST 꼬리를 줄였는지(기준선 대밸)를 따로 적는다. **이 항목은 사전등록된 취소 기준을 바꾸지 않는다** — 판정은 위 실험 목록의 각 행이 그대로 하고, TEST 꼬리는 결과 보고의 별도 열이다. `rounds.csv`의 `finding_scope` 열(prod|test|plan|mixed|none)이 그 기록이다.

C1의 예상: 게이트가 결함의 재현을 새 헤드에서 다시 돌리므로, “가드가 vacuous하다”는 TEST 결함은 변이가 다시 살아나는지로 증명된다. 따라서 C1은 생산 코드 결함 축보다 TEST 꼬리를 더 직접적으로 줄일 수 있다 — 이는 예측이며, 판정은 위 기준으로 한다.

## 기록 형식

실행(run)은 최종 보고에 **회차별 상세**를 남깁니다: 회차, 판정 헤드, dispatch 시각, verdict 시각, 분, 결함 수, 게이트 행, PR 단위 호출 수, step 12 결과.

시리즈 실행자는 이 장부에 **PR 단위 요약**을 남깁니다:

```
| PR | 실험 | 열림→병합(분) | 회차 수(REVISE+not fixed) | 회차별 분 | 게이트 행 fixed/not fixed/no command | 결함 수 | step12 | 재수정 | 비고 |
```

블록 단위 표(품질 확인):

```
| 블록 | 실험 | 표본 5 PR | blind 재리뷰 결과 | 재수정 여부 | 판정 |
```

## 무효 표본

세션이 멈춘 구간(공급자 524, 장애)이 섞인 열림→병합 시간은 무효로 표시하고 중앙값에서 제외합니다. 짝 비교는 같은 부류·비슷한 크기만 사용합니다.
