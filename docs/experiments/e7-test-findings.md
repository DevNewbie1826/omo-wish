## 가설

최종 리뷰(9단계)에서 테스트 코드에 대한 지적을 **재현이 있는 세 경우로만** 차단 사유로 인정하면, 리뷰어가 테스트 스타일·커버리지 의견으로 PR을 계속 되돌리는 꼬리가 끊겨 열림→병합 시간이 줄고, 생산 코드 결함 검출은 그대로 유지된다.

근거(측정 보고서 `/tmp/oru-revise-tests/report.md`, 2026-10-27):

- genie 열린 9 PR: REVISE 43라운드 중 **16이 테스트 전용(37.2%)**, 블로킹 파인딩 27/99(27.3%).
- PR #63(F83) 한 건이 **2026-10-26 23:27 이후 15라운드 연속 테스트 전용 REVISE**, 20.7시간. 각 라운드의 판정 문구는 "No production defect was reproduced"였습니다. #63을 빼면 열린 PR은 1/13(7.7%)입니다.
- 병합 104 PR 기저: 회수한 74라운드 중 테스트 전용 10(13.5%), 파인딩 13/68(19.1%).
- agent-sense 22라운드 중 7(31.8%), 파인딩 10/73(13.7%).
- 시간 축: 최종 리뷰 REVISE 0 PR의 열림→병합 중앙 51.3분(n=62), REVISE ≥1은 171.8분(n=42). 꼬리(≥4회) 8/104.

즉 이 팔이 겨냥하는 것은 **평균이 아니라 꼬리**입니다. 테스트 전용 라운드가 한 번도 없는 PR에는 영향이 없고, 꼬리가 붙은 PR에서만 회차가 줄어듭니다.

## 단일 변수

바뀌는 것: **리뷰 판정에서 테스트 코드 지적이 차단이 되는 조건.**

- 차단: (a) 생산 코드 결함이 재현됨, (b) 가드 변이가 살아남음(가드를 지워도 테스트가 통과), (c) vacuous·flaky 테스트가 재현됨 — 셋 다 보고서에 재현 기록(명령·변이·출력)이 있어야 합니다.
- 비차단: 그 밖의 테스트 스타일·구조·커버리지·"더 강한 단언" 의견. 메모로만 기록되고 REVISE 사유가 아닙니다.
- 그 메모만 있는 라운드는 메모를 기록한 채 **APPROVED**로 끝납니다.
- 예외 하나: **IS·COMPANION 행이 요구하는 테스트가 아예 없으면 그 행 미달**로 차단합니다(행 ID와 테스트가 없다는 경로·명령 필요). 테스트를 지우거나 만들지 않고 넘어가는 구멍을 막는 조항입니다.

바뀌지 않는 것:

- 5단계 주입 검사, 6단계 변이 검사(guard 행마다 변이 하나), 저장소 테스트, 7단계 코드 리뷰. 테스트 요건은 하나도 줄지 않습니다.
- 유한한 계약(불변식·IS/COMPANION 행), 3단계 계획 리뷰의 차단 정의, 리뷰어 수·모델, 라운드 순서, 8·11·12·13단계.
- **테스트를 QA 시나리오로 대체하지 않고, 계획·프롬프트·보고서에서 테스트 언급을 지우지 않습니다.** (소유자 지시의 명시 조건)

파일: `skills/wish/SKILL.md`(9·10단계, Rules의 테스트 줄, Delegation prompts의 리뷰어 규칙 원문), `skills/wish/references/review.md`(Step 9, Step 10의 `Test-code findings`, Step 11의 APPROVED), `README.md`(13단계 9·10, 지키는 규칙의 테스트 줄, 새 절 `테스트 코드 지적`), 이 문서.

## 취소 기준 (사전 등록)

- **표본 단위**: **처치 PR** = 최종 리뷰가 E7 문구가 들어간 프롬프트로 실행된 PR. 같은 PR의 2회차 이상, 델타 라운드도 그 PR의 기록에 포함합니다(회차 단위는 `rounds.csv` 규칙). E7 문구 없이 돈 라운드는 그 PR을 처치로 세지 않습니다.
- **1차 지표**: 열림→병합 중앙(분). 같은 창에 대조 팔로 배정된 PR이 있으면 그 중앙과 비교하고, 없으면 기준선 92.8분을 씁니다.
- **2차 지표(꼬리)**: 테스트 전용 REVISE 라운드 수·비율, PR별 최대 연속 수.
- **3차 지표(준수)**: 재현 없는 테스트 REVISE 라운드 수(`unreproduced_test_revise_rounds`), 메모만 있는데 REVISE로 끝난 라운드 수(`memo_only_revise_rounds`). 둘 다 0이어야 합니다.
- **판정 시점**: 처치 PR **12건**. 6건 시점은 진단 기록만 하고 취소 게이트로 쓰지 않습니다(품질 가드는 상시).
- **판정 순서**(장부 공통 순서):
  1. (0) 공통 품질 가드 위반 → **취소**.
  2. (1) 취소 조건: `unreproduced_test_revise_rounds ≥ 1` **또는** `memo_only_revise_rounds ≥ 1` **또는** 열림→병합 중앙 **≥ 92.8분**(개선 미증명) **또는** PR별 최대 연속 테스트 전용 REVISE **> 2** **또는** 테스트 전용 REVISE 라운드 비율 **> 13.5%**(기준선 악화) → **취소**.
  3. (2) 계속 조건: 열림→병합 중앙 **≤ 83.5분**(기준선 −10%)이고 위 취소 조건이 전부 거짓 → **계속(kept)**.
  4. (3) 83.5분 < 중앙 < 92.8분이면 **6 PR 연장(총 18)** 후 (0)~(2)로 한 번 더 판정하고, 연장 뒤에도 (1)·(2) 어느 쪽도 아니면 **취소**. 연장은 1회뿐입니다.
- **품질 가드(하나라도 걸리면 즉시 취소, 공통 4종)**:
  1. 병합 후 12단계(병합 뒤 전체 검증) 실패.
  2. 병합 뒤 그 PR을 다시 고치는 커밋/PR.
  3. **blind 재리뷰에서 계약 안 결함 발견** — 아래 절차로 승인 PR 5건을 다시 보고, E7이 메모로 돌린 테스트 지적이 실제로는 (a) 생산 결함이나 (b) 살아남은 가드 변이였음이 드러나면 취소.
  4. 꼬리(REVISE ≥4) 비율 악화(기준선 8/104 = 7.7/100 초과).

### 놓친 실제 결함 검출 — 승인 PR 5건 blind 재리뷰

1. **표본**: 판정 시점에 APPROVED로 병합된 처치 PR에서 **무작위 5건**(병합이 5건 미만이면 전부). 무작위 추출은 `shuf`로 하고, 뽑힌 PR 목록과 시드를 PR 본문에 남깁니다.
2. **리뷰어**: E7 팔과 다른 모델 계열, E7 문구가 없는 프롬프트로 1회.
3. **입력**: PR diff와 계획의 유한한 계약(불변식·IS/COMPANION 행)만. 그 PR의 원 리뷰 보고서는 주지 않습니다.
4. **판정 기준**: 계약 안 코드 결함. 그중 **원 최종 리뷰가 테스트 지적으로 메모 처리한 항목이 (a) 생산 결함 또는 (b) 살아남은 가드 변이로 재현되면** 품질 가드 3 → 즉시 취소.
5. **가드에 세지 않는 것**: E7과 무관한 일반 리뷰어 실수(예: E7이 다루지 않는 생산 코드 결함을 원 리뷰가 그냥 놓친 경우). 이것은 기준선 리뷰어 오류율로 따로 기록하고, 가드 3은 "E7이 강등해서 놓친 것"에만 적용합니다.
6. **기록**: `measurements.csv`의 `blind_rereview` 열에 `5건: 결함 N건(E7 기인 M건)` 형식으로 적습니다.
